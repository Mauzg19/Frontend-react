# Validación de ESLint y CI estricto

El 18/11/2026 se corrigieron las 143 advertencias originales en la rama fix/sustentacion-restaurant-fast. El análisis de 126 archivos JavaScript y JSX termina con cero errores y cero advertencias. Se conserva la configuración de ESLint y se agrega `npm run lint`, que exige `--max-warnings=0`.

## Cambios

Se retiraron imports, estados y variables sin uso. Los efectos de sesión y restaurante dependen del token efectivo, del rol y del identificador correspondientes. Los pedidos esperan a tener restaurante y token, y reaccionan al filtro. El panel carga el menú cuando llega el restaurante del propietario. Los cambios equivalentes del objeto de perfil o restaurante no disparan consultas repetidas.

Las comparaciones de rol usan igualdad estricta. El decremento del último elemento del carrito conserva compatibilidad con cantidad numérica o texto numérico; sus controles tienen nombres accesibles. Se añadieron cuatro pruebas de regresión para sesión, llegada del restaurante, renovación del token y eliminación del último elemento.

## Resultados

- `npm run lint` aprobado con cero advertencias y errores en 126 archivos.
- `CI=true npm run build` aprobado con `Compiled successfully`.
- Suite React completa aprobada, 10 pruebas en 5 suites.
- Tres rondas de roles, compra y flujos secundarios, tres de predicción y una de cocina. Trece ejecuciones E2E positivas sobre el build de producción con una base sintética nueva.
- Verificados visitante, cliente, propietario, administrador y gerente, incluyendo redirecciones, permisos, favoritos, notificaciones y cierre de sesión.
- Compra con foto y pago simulado local, relectura del pedido pagado y transición de cocina persistida tras recarga.
- Registro, creación/edición/eliminación de direcciones, restablecimiento de contraseña mediante SMTP local, eventos y productos con foto, con relectura por API.
- Cinco escenarios del modelo v2, tres anchos, entradas inválidas y recuperación tras 503.
- Mutantes detectados por su causa esperada. El pedido simulado sin persistencia falla al releer el servidor; la predicción +10 falla al cotejarla con Keras. Ambos terminaron en exit 1 sin timeout.

Tras reducir los cambios de formato, los seis archivos ejecutables JS/CSS/HTML/JSON del build revisado coinciden byte a byte con el artefacto probado en E2E. Las huellas y recibos figuran en [resultado portable](eslint-ci-2026-11-18.json). Evidencia completa local en qa-eslint-20261118/evidence, junto a los repositorios.

## Repetir

```powershell
npm ci
npm run lint
$env:CI='true'
npm test -- --watchAll=false --runInBand
npm run build
```

Los avisos del tooling de Create React App/Babel y Browserslist son distintos de los diagnósticos ESLint. El build estricto se verificó conservando esa cadena de herramientas. Los pagos de la regresión usan un simulador local; la prueba remota de Stripe y el teléfono físico siguen aplazados por decisión del usuario.
